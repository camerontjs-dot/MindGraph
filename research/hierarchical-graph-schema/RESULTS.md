## First-result ledger, including genuine failures

1. **RC0 (first source projector):** real code/file navigation 7/7; direct Git/source baseline 7/7; SQL path comparator 7/7; synthetic path expectations 7/7; initial controls 8/8. **Subsequent identity mutation falsifiers exposed two accepted invalid records:** an edge pointed to an unrelated but existing Git source; a source's Git blob SHA was falsified while retaining its ID. This predecessor is **NOT QUALIFIED** and its exact failures are preserved in the private local evaluation area.
2. **RC1 (separate source-instance validator and actual Git-object attestor):** original cases still passed; exact pinned Git blobs, Python AST declarations and source-line imports attested. **Pressure control 11/12**, because a Git source flipped from allowed to denied but remained accepted. Preserved as `FAILED_PROVENANCE_CONTROL`, not reinterpreted as success.
3. **RC2 (source access/citation gate):** original cases and **12/12** source/authority pressure controls passed, with immutable record and byte-comparison checks. Graph-only internal identity is insufficient: a fully consistently rekeyed false blob was correctly rejected by the independent-formula actual Git-object attestor.
4. **RC3 (portability successor):** a public-only reproduction legitimately reported private Knowledge/Operations inputs unavailable, then the attestor attempted to hash the nonexistent outputs and failed. The failed first invocation is preserved, **not a qualified public-only run**.
5. **RC4 (public/private execution separated):** the initial combined command mistakenly invoked a full-corpus pressure check against a public-only graph and failed; this is an operator entrypoint/apparatus error, not a repaired green result. Separate public-only and full runs using the unchanged source code then finished successfully, each with its own manifest and receipts.
6. **RC5 (portable pressure invocation):** only the pressure script was adapted to accept separately supplied projection/cases/output locations. Its projector, source-binding validator, attestor, case inputs and schema remained **byte-identical to the independently run RC4 sources**. Public-only pressure returned **11/11 PASS**, with the unavailable Knowledge mutation explicitly `NOT_RUN_UNAVAILABLE`; full-corpus pressure returned **12/12 PASS**. The public and full projection outputs retained their exact hashes.

Research branches retain their own immutable Git evidence; a candidate repair does not change an older result. These controls are *separately implemented formula/source checks* with some shared authoring context, **not an isolated independent semantic adjudicator**.

## Decision and boundary for next work

**Recommend freezing the research schema as a bounded v0.3 candidate:** one scope/view per project pinned to an exact Git commit, Knowledge notes distinct from time-bound Operations, a cheap versioned directory catalogue, and source-backed, access-aware hop witnesses for any later explicit cross-scope relationship. Reuse standard Git, SQLite, and code symbol indexers rather than build a new knowledge graph engine.

The following remain unqualified and must not be claimed:

- Actual improvement in downstream agent task correctness, time, tokens, or user value relative to search and SQL;
- Fully parsed Swift symbol/call relations; dynamic Python call graph; dependency/test/qualification inference from name similarity;
- Full MainFrame multi-project graph; GitHub PR/issue lineage and current state inside this research project;
- Complete Knowledge concept/entity ontology, Evidence Room warehouse replication, current Operations source freshness;
- Live cross-scope consumer path authorization or true runtime Conduit/MindGraph binary identity;
- Independently sourced task oracle, independently isolated model actor and live production integration;
- Broad replacement of maintained MainFrame/MindGraph, schema migration, release or endorsement of an additional graph database.

MainFrame #80 / MindGraph #33–35 agent-isolation blockers remain binding. Any schema promotion or user-facing deployment needs a **separately qualified actual consumer** and independent owner decision. A source-backed code-graph or cross-scope extension should have a new frozen schema version and negative controls, not rewrite this v0.3 historical evidence.

**A defensible representation has been obtained for the tested boundary; universal/operational graph utility remains unproven.**
